# Сценарій демонстрації на захисті

Перед демонстрацією виконайте команди з README: встановлення залежностей, міграції, `seed_demo`, `createsuperuser`, запуск сервера.

1. Відкрийте `/catalog/maps/`. Поясніть тему й покажіть карти. Знайдіть `Island`, змініть сортування, відкрийте деталі та інтерактивну карту.
2. Відкрийте `/catalog/places/`. Відфільтруйте локації за картою й виконайте текстовий пошук. Поясніть, що запити виконуються Django ORM, а не лише приховують елементи в браузері.
3. Зареєструйте користувача. Додайте власну PvE-локацію з координатами, покажіть сторінку деталей, змініть назву та збережіть. Спробуйте ввести координату 101 — форма має показати помилку.
4. Створіть PvP-локацію, вибравши тип, розташування, динозавра, кількість входів і оцінку. Довідники вже створено командою `seed_demo`.
5. Відкрийте відповідну інтерактивну карту. Знайдіть маркер, поставте оцінку, додайте локацію до обраного й покажіть її у профілі.
6. Увійдіть під іншим звичайним користувачем: кнопок редагування чужих локацій немає. Запит до чужої форми зміни має отримати HTTP 403.
7. Увійдіть під адміністратором через звичайну сторінку входу. Створіть тестову карту без зображень, змініть її назву, перегляньте деталі, видаліть після підтвердження. Покажіть, що карту з локаціями видалити неможливо.
8. Покажіть `/admin/`: фільтри, пошук, довідники, завантаження медіа. Поясніть різницю між власником локації та адміністратором.
9. Видаліть власну тестову локацію. Відкриття сторінки підтвердження саме по собі нічого не видаляє; потрібен POST через кнопку.
10. Запустіть `python manage.py test --noinput` у віртуальному середовищі та покажіть результат. Відкрийте таблицю відповідності вимогам у README.

## Що пояснити в коді

- `maps/models.py`: зв’язки `Map → Spot/Place`, оцінки, Many-to-Many, `PROTECT` для карти.
- `maps/catalog.py`: пошук через `Q`/`icontains`, фільтр, сортування, пагінація, перевірка власника.
- `maps/forms.py`: ModelForm і валідація координат.
- `accounts/views.py`: створення звичайного користувача без адміністративних прав.
- `maps/test_catalog.py`: перевірки HTTP-відповідей і фактичних змін у тестовій базі.

Демонстраційні локації вигадані. Пароль адміністратора створюється локально; персональна база й облікові дані не публікуються.
