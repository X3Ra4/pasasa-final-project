# REST API

Base URL локального Compose: `http://127.0.0.1:8088/api/`.
Формат JSON; списки мають `count`, `next`, `previous`, `results`; 30 записів на сторінці.
Вебформа API доступна в браузері після входу в сайт. Секретні дані не включаються у відповіді.

## Авторизація

1. **Session:** увійти через `/accounts/login/`; запити зміни в браузері потребують CSRF.
2. **Token:** адміністратор генерує токен для наявного активного користувача:

```sh
docker compose exec web python manage.py drf_create_token your_username
```

Команда показує секретний токен один раз у терміналі; не додавайте його в Git чи скриншоти.
Запит містить `Authorization: Token YOUR_TOKEN`. У публічній мережі використовуйте HTTPS.
Токен відкликається видаленням у `/admin/authtoken/tokenproxy/`; деактивація акаунта також блокує доступ.

```http
GET /api/tasks/?status=doing&sort=due HTTP/1.1
Authorization: Token YOUR_TOKEN
Accept: application/json
```

## Маршрути

| Метод | Шлях | Поведінка |
|---|---|---|
| GET, POST | `/api/projects/` | Доступні проєкти / створення власного |
| GET, PUT, PATCH, DELETE | `/api/projects/{id}/` | Деталі; зміна/видалення лише власником |
| GET | `/api/projects/{id}/stats/` | total, active, done, overdue |
| GET, POST | `/api/tasks/` | Доступні активні завдання / створення власником проєкту |
| GET, PUT, PATCH, DELETE | `/api/tasks/{id}/` | Читання / зміна / видалення з перевіркою ролі |
| GET, POST | `/api/tasks/{id}/comments/` | Коментарі / додати власний коментар |
| GET | `/healthz/` | Перевірка доступності БД, поза префіксом API |

Приклад створення проєкту:

```json
{"name": "Навчальний план", "description": "Завдання поточного модуля"}
```

Приклад створення завдання (IDs беруться з вашої бази):

```json
{"project": 1, "title": "Підготувати демонстрацію", "description": "Перевірити основні сценарії", "assignee": null, "status": "todo", "priority": "high", "due_date": "2026-12-20"}
```

Виконавець може надсилати лише `PATCH {"status":"doing"}` для свого неархівованого завдання.
Будь-які додаткові поля від учасника відхиляються. Власник змінює всі редаговані поля,
але перенесення на інший проєкт заборонено. `PATCH {"archived":true}` архівує,
`PATCH {"archived":false}` відновлює. Власник і час створення не задаються клієнтом.

Коментар: `POST {"body":"Готово до перевірки"}`. Автор визначається з авторизації.
Керування складом команди в цій версії здійснюється через сайт, не API.

## Фільтри списку завдань

`project=<id>`, `q=<text>`, `status=todo|doing|done`, `priority=low|normal|high`,
`assignee=<id>|none`, `archived=1`, `sort=new|due|priority`, `page=<number>`.
Без `archived=1` список виключає архів. Деталі доступного архівного завдання залишаються доступними за ID.
Невідомі значення фільтрів і некоректні числові IDs ігноруються, не розширюючи доступ за межі власних проєктів.

## Помилки

400 — помилка валідації; 403 — немає авторизації/дозволу або CSRF; 404 — об’єкт відсутній
чи недоступний; 405 — заборонений метод; 429 — перевищено 300 API-запитів за хвилину на користувача.
Ліміт у стандартному локальному cache є захистом від випадкового навантаження, не загальнокластерним лімітом.
`/healthz/` повертає 200 `{"status":"ok"}` або 503 `{"status":"unavailable"}` без деталей підключення.

Правила доступу враховують [особливості object permissions DRF](https://www.django-rest-framework.org/api-guide/permissions/):
списки фільтруються окремо, а створення та зміни мають власні перевірки.
